## 摸鱼阅读工具 — 视觉现代化改造

按用户"保持功能逻辑不变"的要求，重构整套 UI 样式。

### 改动文件
- **新增** `theme.py` —— 集中设计令牌（主色/辅助色/中性色、字体、间距、圆角）+ 统一 QSS 生成器
  - `COLORS`：主色 `#0E7490`（深青）、辅助色 `#F59E0B`（琥珀）、Slate 系中性色、深色玻璃浮层
  - `FONT_FAMILIES`：Microsoft YaHei UI → Microsoft YaHei → Segoe UI（带回退链）
  - `build_stylesheet()`：应用级全局 QSS（标签页、按钮、滑块、复选框、下拉框、菜单、卡片等）
  - `toolbar_qss()`：阅读器深色玻璃拟态工具栏样式
  - `reader_document_css()` / `reader_list_qss()`：阅读正文 / RSS 列表（保留透明度隐身语义）
  - `fade_in(widget)`：淡入动画（`QGraphicsOpacityEffect` + `QPropertyAnimation`，效果对象缓存在 widget 上避免泄漏）
  - `apply_shadow(widget)`：用 `QGraphicsDropShadowEffect` 实现柔和投影（Qt QSS 不支持 box-shadow 的替代方案）
  - `_icon()`：用 `QPainter` 现画对勾 / 箭头小图标（运行时画一次落盘缓存）
- **重写** `main.py` —— 移除 `qt_material`；改用全局样式表 + 对象名（`PageTitle` / `CardTitle` / `BookName` / `Muted` / `Badge`）
  - 标签页：胶囊选中态（主色浅底 + 主色文字）
  - 设置页：三张分组卡片 + `QGraphicsDropShadowEffect` 柔和投影
  - 书籍项：白底卡 + 悬停态（主色浅边框 + 浅底）
  - "阅读"按钮：实心主色填充（`setProperty('class', 'primary')` + `[class="primary"]` 选择器）
  - `setMinimumSize(430, 560)` 保证小窗口布局不破碎（响应式）
  - 颜色按钮：圆角 6px 描边
  - 修复：`QColorDialog` 在 PyQt6 中位于 `QtWidgets`（原代码从 `qt_material` 间接导入）
- **重构** `reader.py` —— 浮动工具栏 / 托盘菜单 / 右键菜单样式统一
  - 工具栏：深色玻璃拟态（半透明深色 + 14px 圆角 + 1px 半透明白边 + 24px 按钮）
  - 图标配色：原先黑图标在深色工具栏上对比度差 → 全部改为 `glass_text`（浅灰白）
  - 工具栏按钮 hover/press 状态用 `QGraphicsOpacityEffect` 实现柔和淡入
  - 正文排版：行高 1.8 → 1.9、padding 50/100 → 40/44（更紧凑）
  - RSS 列表：圆角条目 + 悬停态、保留透明度隐身语义（背景色随设置联动）

### 验证
- 离屏冒烟测试：MainWindow / EpubReader / RSS 列表样式函数 / 工具栏淡入 全部通过
- 离屏渲染验证布局：标签页胶囊态 ✓ 卡片阴影 ✓ 主色按钮 ✓ 滑块/复选框 ✓ 深色玻璃工具栏 ✓
- 离屏环境无中文字体库（仅 QFontDatabase 找不到 CJK family），中文显示为方框——这是测试环境限制，用户实际 Windows 桌面有 MS YaHei 不受影响

### 设计决策
- 主色沿用原 teal 色系（`#2f90ba` → `#0E7490`，更深的 cyan-700）保持视觉基因
- 透明度 + 圆角 + 柔和投影作为现代视觉三件套
- Qt QSS 不支持 `box-shadow` 和 CSS `transition`，所以阴影用图形效果、动效用 `QPropertyAnimation` 曲线
- 阅读器阅读窗口的功能（鼠标进出隐藏工具栏、滚轮翻章、缩放、置顶）全部保持原样
- 国际化（"颜色" / "字号" / "字体" / "敬请期待" / "🔄 刷新列表" 等文本）保持原文不翻译

## 少数派 RSS 全文修复

### 根因
- 少数派官方 RSS `https://sspai.com/feed` 的 `<description>` 只含截断摘要 + "查看全文"链接，无 `content:encoded` 全文字段
- `show_detail` 对所有源统一走 `entry.content[0].value if hasattr(entry,'content') else entry.summary` → sspai 取到摘要 → 经 `clean_zhihu_html` 清洗后只剩摘要文本

### 修复方案（reader.py）
- 新增模块级 `fetch_sspai_article_html(url)`：用 urllib 抓文章页 → BeautifulSoup 提取 `<div class="article__main__content">`（服务端渲染，普通长文/早报/合集三类均通过此容器，已实测验证）
- 新增 `ArticleLoaderThread(QThread)`：异步抓取单篇全文，`loaded = pyqtSignal(str, object)` 回传 (url, html_or_None)
- `RSSWindow.__init__` 增 `self._article_cache = {}`、`self._article_thread`、`self._current_detail_entry`
- `show_detail` 增 sspai 分支 → `_show_sspai_detail`：
  1. 命中缓存（含失败 None 缓存）直接渲染
  2. 未命中：先用摘要即时展示"正在加载全文…"，再启 ArticleLoaderThread
  3. `_on_article_loaded`：写缓存 → 仅当用户仍停留该文章时渲染全文，否则丢弃；失败用摘要兜底
- `closeEvent` 增加对 _article_thread 的 quit/wait 清理
- 其他源（知乎/IT之家/爱范儿）逻辑完全不变

### 验证
- 真实网络实测 3 篇文章全文：摘要 164-168 字 → 全文 1337/2437/6534 字（8-40 倍）
- ArticleLoaderThread 信号链路 OK（html 11694 字节）
- 分支逻辑同步验证：成功渲染+缓存 / 用户切走不渲染 / 失败摘要兜底+缓存None / 缓存命中不重建线程 全部通过
- 离屏 QTextBrowser.setHtml 渲染大段 HTML 会段错误（exit 127），属测试环境限制；真实 Windows 桌面与其他三个源走同一渲染路径，不受影响

### 二次修复：全文阶段标题丢失
- **根因**：`_render_sspai_article(entry, html)` 全文到达时用的是裸正文 HTML（`article__main__content` 容器只含正文段落/小节，不含文章主标题），而加载阶段经 `_wrap_sspai_html` 包了 `<h3 class="chapter-title">`，全文一到就被无标题裸 HTML 覆盖 → 主标题凭空消失，只剩正文小节
- **修复**：重构 `_render_sspai_article(entry, body_html, note="")` 让它统一负责"标题+正文+提示"的包装（内部调 `_wrap_sspai_html`），所有调用点只传裸正文 + 可选 note：
  - 加载阶段：`_render_sspai_article(entry, entry.summary, note="正在加载全文…")`
  - 全文到达：`_render_sspai_article(entry, html)`
  - 失败兜底：`_render_sspai_article(entry, entry.summary, note="全文加载失败，以下为摘要")`
  - 缓存命中：`_render_sspai_article(entry, cached)`
- **验证**：四个场景标题全部保留（True），全文阶段 6 个 `<h3>`（1 主标题 + 5 小节），纯文本 1374 字完整

### 四次修复：派早报无法显示全文（真正根因）
- **前一轮误诊**：以为早报真实正文不在 SSR HTML 里，加了"回退到 RSS 摘要"的补丁——这是错的根因判断
- **真正根因**：早报的真实新闻**在另一个容器里**，不是 `article__main__content`
  - 普通长文正文容器：`<div class="article__main__content wangEditor-txt>`
  - 派早报正文容器：每条新闻在 `<div class="post__body__extend__item">` 内，含 `<h2 class="post__body__extend__item__title">` 标题 + `<div class="post__body__extend__item__content wangEditor-txt">` 正文
  - 早报的 `article__main__content` 装的是站点推广位（"近期动态/会员启航/你可能错过的好文章/下载客户端"），不是新闻
- **修复方案**（reader.py `fetch_sspai_article_html`）：
  - 先 `soup.find_all("div", class_="post__body__extend__item")`——若有（早报），拼接每条的 h2 标题 + content 正文
  - 否则回退到 `article__main__content`（普通长文，原逻辑）
  - 移除上一轮的 `_resolve_content` / `_summary_present_in` / `fallback_summary` / `_wrap_summary` 全部补丁代码（基于误诊）
  - `ArticleLoaderThread.__init__` 恢复为只接 `url`
  - `_show_sspai_detail` 启动线程改回 `ArticleLoaderThread(url)`
- **验证**：RSS 全 10 篇文章——2 篇早报（3852/3569 字，含 7/5 个 h2 新闻条目）+ 8 篇长文（1337-9052 字）全部完整提取
- **根因**：`_render_sspai_article(entry, html)` 全文到达时用的是裸正文 HTML（`article__main__content` 容器只含正文段落/小节，不含文章主标题），而加载阶段经 `_wrap_sspai_html` 包了 `<h3 class="chapter-title">`，全文一到就被无标题裸 HTML 覆盖 → 主标题凭空消失，只剩正文小节

  - 加载阶段：`_render_sspai_article(entry, entry.summary, note="正在加载全文…")`
  - 全文到达：`_render_sspai_article(entry, html)`
  - 失败兜底：`_render_sspai_article(entry, entry.summary, note="全文加载失败，以下为摘要")`
